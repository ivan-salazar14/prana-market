+# Prana Market ÔÇö Technical & Architectural Addendum
+
+This document captures architectural specifications, integration schemas, and downstream implementation details for downstream BMad skills (`bmad-architecture`, `bmad-ux`, `bmad-create-epics-and-stories`).

+---
+
+## 1. Technical Stack Architecture
+
+- **Frontend**: Next.js 16 (App Router, Turbopack, React 19, Tailwind CSS v4, Lucide Icons, Framer Motion).
+- **Backend CMS & API**: Strapi v5 (TypeScript, PostgreSQL database, Cloudinary media provider, Users-Permissions plugin).
+- **Payment Processing**:
+  - **Primary**: Wompi API (Nequi Direct Push / QR, PSE, Bancolombia, Credit/Debit cards, Efecty/Baloto cash vouchers).
+  - **Secondary**: Stripe API (International cards / Apple Pay in COP).
+- **Dropshipping Engine**: Mastershop Integration Service (REST API & Webhooks).
+
+---
+
+## 2. Mastershop Dropshipping Integration Mechanism
+
+### 2.1 Ingestion Pipeline
+1. **Catalog Polling / Webhook**: Strapi cron job periodically syncs with Mastershop `/api/products` or listens to product catalogue update webhooks.
+2. **Schema Mapping**:
+   - Mastershop Product ID $\rightarrow$ `strapi::product.external_id`
+   - Mastershop Inventory Level $\rightarrow$ `strapi::product.dropship_stock`
+   - Mastershop Base Cost $\rightarrow$ Applied Margin Formula $\rightarrow$ `strapi::product.price`
+3. **Media Synchronization**: Images uploaded and optimized to Cloudinary CDN with responsive breakpoints.
+
+### 2.2 Order Forwarding & Fulfillment Flow
+```

+## 3. Colombian Payment Handling (Nequi & Wompi)
+
+- **Signature Generation**: Backend generates SHA-256 integrity signature (`WOMPI_INTEGRITY_SECRET`) for each checkout session.
+- **Nequi Direct Flow**: Customer submits phone number $\rightarrow$ Wompi sends immediate push notification to customer's Nequi app $\rightarrow$ Backend polls or waits for webhook confirmation $\rightarrow$ Success modal rendered on frontend.
+- **Idempotency**: All webhook handling uses unique `transaction.id` to prevent double-crediting or duplicate dropship order dispatch.

+- **Backend CMS & API (`backend/`)**: Strapi v5 on Node.js with PostgreSQL. Houses product catalog, user permissions, order lifecycle state machine, and administrative dashboards.
+- **Integration Bus & Workers**: Asynchronous webhook consumers for payment settlement (Wompi, Stripe) and scheduled background cron workers (`node-cron`) for Mastershop catalog/inventory synchronization.

+## Invariants & Rules
+
+### AD-1 ÔÇö Single Source of Truth for Orders & Status Orchestration `[ADOPTED]`
+
+- **Binds:** `FR-PAY-01..04`, `FR-ADM-01`, `FR-DROP-03`
+- **Prevents:** Distributed or conflicting order status between frontend, payment providers, and dropship suppliers.
+- **Rule:** All order entities (`api::order.order`), status transitions (`pending` -> `paid` -> `processing` -> `shipped` / `delivered`), and fulfillment dispatches must execute exclusively within Strapi backend services. The Next.js frontend is strictly a consumer and must never directly mutate order lifecycle status or trigger supplier APIs.
+
+### AD-2 ÔÇö Cryptographic Webhook Verification & Idempotent Payment Settlement `[ADOPTED]`
+
+- **Binds:** `FR-PAY-01`, `FR-PAY-02`, `FR-PAY-04`, `NFR-SEC-03`
+- **Prevents:** Duplicate order fulfillment, payment replay attacks, or race conditions upon multiple webhook retries.
+- **Rule:** All incoming payment webhooks (`/api/payment/wompi-webhook`, `/api/payment/stripe-webhook`) must compute and verify HMAC SHA-256 signatures using `WOMPI_INTEGRITY_SECRET` / `STRIPE_WEBHOOK_SECRET`. Webhook processing must be idempotent: checking `orders.transactionId` and current status before transitioning to `paid`. If already processed, respond immediately with HTTP 200 without re-triggering fulfillment.
+
+### AD-3 ÔÇö Unified Cart with Hybrid Sourcing Partitioning `[ADOPTED]`
+
+- **Binds:** `FR-CAT-03`, `FR-DROP-01..03`, `UJ-2`
+- **Prevents:** Cart fragmentation, multiple checkout steps, or inventory collisions between local stock and dropshipped products.
+- **Rule:** A single cart and single checkout order accommodates mixed products. The Strapi `Order` entity stores items with an explicit fulfillment discriminator (`sourcing_type`: `"local"` | `"mastershop_dropship"`). Dropship items preserve `mastershop_id`, `supplier_sku`, and supplier cost for automated post-payment routing.
+
+### AD-4 ÔÇö Asynchronous Mastershop Dispatch & Fault Isolation `[ADOPTED]`
+
+- **Binds:** `FR-DROP-03`, `FR-DROP-04`, `FR-ADM-02`
+- **Prevents:** Payment webhook timeouts caused by external supplier API delays, and order loss during supplier downtime.
+- **Rule:** Mastershop order creation (`POST /api/orders/create`) is triggered asynchronously after payment confirmation is committed to PostgreSQL. Transient API failures must not roll back payment status; failures are recorded in `orders.mastershop_data.error` with `sync_mastershop: true` for automatic retry or manual admin resolution in Strapi.
+
+### AD-5 ÔÇö Client Cart Persistence & DANE Hierarchy Validation `[ADOPTED]`
+
+- **Binds:** `FR-CART-01`, `FR-LOG-01`, `FR-LOG-02`, `NFR-UX-01`
+- **Prevents:** Cart loss during browsing and mismatched Colombian address/shipping rate calculations.
+- **Rule:** Cart items, quantities, and selected delivery options persist in `localStorage` synchronized via React Context. Shipping destination selectors must strictly follow the DANE standard hierarchy (Department -> Municipality -> Neighborhood). Pricing, discounts, and delivery fees calculated on the client are re-verified on the server before generating payment checkout signatures.
+
+### AD-6 ÔÇö Zero-Cardholder-Data Boundary (PCI-DSS Compliance) `[ADOPTED]`
+
+- **Binds:** `NFR-SEC-01`, `FR-PAY-01`, `FR-PAY-02`
+- **Prevents:** PCI-DSS scope expansion and credential leakage.
+- **Rule:** No raw Credit Card PAN, CVV, expiration date, or Nequi security OTPs shall touch or be stored on Prana Market servers. All card tokenization and Nequi push requests are initiated through Wompi Widget / API tokenization endpoints or Stripe SDK on the client.
+
+### AD-7 ÔÇö Cloudinary Media Optimization & Next/Image Pipeline `[ADOPTED]`
+
+- **Binds:** `NFR-PERF-01..03`, `FR-CAT-02`
+- **Prevents:** Slow mobile page loads (LCP > 2.0s) and Cumulative Layout Shift (CLS) caused by unoptimized beauty product images.
+- **Rule:** All uploaded and synced product assets are processed and served via Cloudinary (`@strapi/provider-upload-cloudinary`). Frontend displays catalog media strictly via `next/image` with responsive widths (`sizes="(max-width: 640px) 100vw, 50vw"`), WebP/AVIF formatting, and explicit aspect ratios.

+# prana-market - Epic Breakdown

+## Overview
+
+This document provides the complete epic and story breakdown for prana-market, decomposing the requirements from the PRD, UX Design, and Architecture requirements into implementable stories.

+## Requirements Inventory
+
+### Functional Requirements
+
+FR-CAT-01: Multi-Brand & Category Taxonomy (Hierarchical category tree: Rostro, Ojos, Labios, Skincare, Accesorios, Sets with multi-brand filtering).
+FR-CAT-02: Rich Product Detail Page (PDP) (High-resolution image galleries, shade/color variant swatches, ingredients list, usage guides, and customer reviews).
+FR-CAT-03: Inventory Origin Badge (Explicit indicator if product ships via Express Local Delivery or National Dropshipping).
+FR-CAT-04: Smart Search & Filters (Typeahead search, filters by brand, skin type, finish matte/glow, price range in COP, and in-stock availability).
+FR-CART-01: Persistent Slide-Over Cart (High-speed drawer cart accessible across all pages with real-time state persistence in localStorage and React Context).
+FR-CART-02: Dynamic Shipping Progress Bar (Visual threshold indicator with animated gradient progress toward free shipping threshold).
+FR-CART-03: One-Click Quantity & Variant Adjustment (Instant quantity toggling, variant switching, and removal without page reload).
+FR-CART-04: Coupon & Promo Code Engine (Support for percentage, fixed COP discounts, and promotional coupons).
+FR-PAY-01: Nequi Direct Checkout Flow (Native Nequi payment integration via Wompi API allowing seamless phone-number push approval or dynamic QR code).
+FR-PAY-02: Comprehensive Colombian Payment Gateway (Full integration with Wompi supporting PSE, Credit/Debit cards, Bancolombia transfer, and cash networks Efecty/Baloto).
+FR-PAY-03: Stripe International Backup (Dual-gateway failover and international card acceptance in COP currency).
+FR-PAY-04: Automated Webhook Reconciliation (Asynchronous webhook handler for payment settlement with HMAC signature verification, idempotency keys, and instant status updates).
+FR-DROP-01: Catalog Import & Mapping (Automated synchronization of products, descriptions, variants, and media assets from Mastershop into Strapi CMS).
+FR-DROP-02: Real-Time Stock & Price Sync (Scheduled background workers/cron syncing supplier stock levels and adjusting dynamic margins).
+FR-DROP-03: Automated Order Dispatch (Automatic creation of dropshipping orders in Mastershop upon confirmed payment in Prana Market).
+FR-DROP-04: Multi-Carrier Tracking Ingestion (Ingestion of tracking numbers and courier links like Servientrega, Coordinadora, Interrapid├¡simo pushing automated notifications).
+FR-LOG-01: Colombian Address Matrix (Hierarchical Department -> Municipality/City -> Neighborhood selector matching DANE standards).
+FR-LOG-02: Tiered Delivery Options (Store Pickup Free, Local Urban Express COP $5.000, Regional/National Standard COP $10.000 or calculated carrier rates).
+FR-LOG-03: Order Tracking Portal (Public tracking page allowing customers to track order status by Order Number + Email/Phone).
+FR-ADM-01: Unified Order Management Dashboard (Centralized Strapi admin dashboard displaying order lifecycle status: pending, paid, processing, shipped, delivered, cancelled).
+FR-ADM-02: Dropshipping Status Monitor (Dedicated view for monitoring Mastershop fulfillment sync status, API error logs, and manual override/retry options).
+FR-ADM-03: Customer Service & WhatsApp Integration (Floating WhatsApp chat widget and direct order issue resolution shortcuts).

+NFR-PERF-02: Cumulative Layout Shift (CLS) < 0.05 across all responsive breakpoints.
+NFR-PERF-03: Image optimization pipeline utilizing Cloudinary and Next.js Image with WebP/AVIF formats and responsive sizing.
+NFR-UX-01: Mobile-First Ergonomics with sticky bottom action bars on PDP and cart drawer optimized for one-handed thumb interactions.

+NFR-SEC-02: Colombian Habeas Data Compliance (Ley 1581 de 2012) with explicit consent checkboxes for privacy policy, terms of service, and commercial communication.

+# Prana Market ÔÇö Product Requirements Document (PRD)
+
+## 1. Executive Summary & Product Vision
+
+### 1.1 Vision Statement
+**Prana Market** aspires to be the #1 online cosmetics and makeup destination in Colombia, combining unbeatable competitive pricing with curated high quality and an expansive multi-brand product catalog.
+
+### 1.2 Core Business Model & Hybrid Sourcing
+Prana Market operates a **hybrid inventory model**:
+1. **Owned / Direct Physical Inventory**: High-demand local makeup and beauty products fulfilled directly from local stock (store pickup & local express delivery).
+2. **Automated Dropshipping via Mastershop**: Infinite-aisle expansion offering multi-brand cosmetics without upfront warehousing risks, synced directly via Mastershop APIs/webhooks for automated cataloging, stock tracking, and supplier fulfillment.
+
+### 1.3 Target Audience & Market Positioning
+- **Primary Consumers**: Colombian beauty enthusiasts, students, professionals, and makeup artists seeking trending cosmetic brands at accessible price points with seamless mobile payment methods (Nequi, PSE, cards).
+- **Geographic Focus**: Urban centers (Bogot├í, Medell├¡n, Cali, Barranquilla, Bucaramanga) with nationwide delivery reach across all Colombian municipalities.
+

+## 2. Success Metrics & Counter-Metrics
+
+### 2.1 Primary Business & Conversion Metrics
+- **Mobile Checkout Conversion Rate**: $\ge 3.8\%$ on mobile devices.
+- **Nequi Payment Completion Rate**: $\ge 88\%$ of initiated Nequi transactions completed without drop-off.
+- **Cart-to-Purchase Abandonment Rate**: Under $55\%$ (industry benchmark ~70%).
+- **Average Order Value (AOV)**: Target COP \$85,000+ driven by cross-selling and tiered free shipping thresholds.
+
+### 2.2 Operational & Fulfillment Metrics
+- **Dropshipping Order Processing Latency**: $< 15$ minutes from payment confirmation to Mastershop order dispatch.
+- **Stock Synchronization Accuracy**: $99.5\%$ real-time accuracy preventing out-of-stock purchases.
+
+### 2.3 Counter-Metrics (Guardrails)
+- **Supplier Order Cancellation Rate**: $< 2.0\%$ (must not sacrifice catalog reliability for inventory scale).
+- **Return / Dispute Rate**: $< 1.5\%$ of shipped orders.
+- **Page Load Time (LCP on Mobile 4G)**: Under 2.0 seconds (preventing image-heavy beauty assets from degrading checkout speed).

+- **Context**: Manages local inventory, monitors Mastershop synchronization, updates promotions, and tracks dispatch status.

+## Component Patterns (Behavioral)
+
+### 1. Slide-Over Cart Drawer (`cart-drawer`)
+- **Trigger**: Opening occurs automatically upon tapping "A├▒adir al Carrito" on PDP or clicking the header bag icon.
+- **Backdrop & Dismissal**: Clicking outside the drawer, pressing `Escape`, or swiping right on mobile collapses the drawer with an animated spring transition.
+- **Optimistic State**: Tapping `+` or `-` on item quantities immediately recalculates subtotal, taxes, and the dynamic free shipping progress bar without blocking UI spinners.
+- **Split Shipment Breakdown**: If the basket contains mixed products (Local Express + Mastershop Dropship), the drawer groups products into two visual delivery cards:
+  - Card 1: `­ƒôª Env├¡o Expr├®s Local (Bogot├í/Medell├¡n: 1-2 d├¡as)`
+  - Card 2: `­ƒî┐ Env├¡o Nacional Dropshipping (3-5 d├¡as h├íbiles)`
+
+### 2. Mobile PDP Sticky Bottom Bar (`pdp-sticky-bar`)
+- **Behavior**: Appears smoothly as the user scrolls past the top product title and hero image gallery.
+- **Controls**:
+  - Left: Mini shade thumbnail swatch & selected shade name (e.g. "Tono 35 Cheeky"). Tapping opens shade drawer.
+  - Center/Right: Dual CTA button cluster:
+    - Primary CTA: `{components.button-primary}` ("A├▒adir al Carrito")
+    - Secondary CTA: `{components.button-nequi}` ("ÔÜí Pagar con Nequi")
+
+### 3. Colombian DANE Address Selector
+- **Behavior**: Cascading dropdowns:
+  - Step 1: Departamento (e.g., Cundinamarca, Antioquia, Valle del Cauca).
+  - Step 2: Ciudad / Municipio (auto-filtered by DANE code).
+  - Step 3: Direcci├│n & Barrio con autocompletado inteligente.
+
+### 4. Nequi Push & Dynamic QR Poller
+- **Behavior**: Upon entering Nequi phone number:
+  1. System sends asynchronous authorization request to Wompi.
+  2. UI displays countdown timer modal (60s) with animated pulse ring.
+  3. Frontend polls transaction status every 2 seconds via Strapi `/api/orders/payment-status`.
+  4. On approval: Instant transition to confetti celebration screen and receipt.
+  5. On timeout/rejection: Gentle recovery screen offering QR retry or alternative payment method (PSE / Tarjeta).
+

+## State Patterns
+
+### Loading States
+- Content loading utilizes subtle skeleton placeholders styled with `{colors.surface-muted}` rather than invasive full-page spinners.
+
+### Error & Recovery States
+- **Card Payment Failure**: Displays specific Colombian decline reason (e.g., "Fondos insuficientes", "Transacci├│n rechazada por el banco emisor") with one-click retry via PSE or Nequi.
+- **Stock Depletion**: If an item in the cart sells out before checkout completion, the cart highlights the affected item with `{colors.status-warning}` and suggests the nearest matching shade variant.

+## Accessibility Floor
+
+- **Touch Targets**: Strictly $\ge 48\times 48\text{px}$ for all touch elements on mobile.
+- **Color Contrast**: All body text and price displays meet WCAG AA (minimum `4.5:1` contrast against `{colors.surface-base}` and `{colors.surface-card}`).
+- **Screen Readers & ARIA**: Cart quantity modifications broadcast live updates using `aria-live="polite"`. Shade swatches announce color name and availability status (`aria-label="Tono 35 Cheeky, disponible"`).
