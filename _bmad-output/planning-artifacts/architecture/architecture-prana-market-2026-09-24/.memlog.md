- (decision) [ADOPTED] Decoupled Headless Commerce Architecture: Next.js 16 (App Router + Turbopack) frontend paired with Strapi v5 (TypeScript + PostgreSQL) headless backend, connected via secure REST API and webhook bus.
- (decision) AD-1: Single Source of Truth for Orders & Status Orchestration. Binds: FR-PAY-01..04, FR-ADM-01, FR-DROP-03. Prevents: Split or conflicting order state across frontend, Wompi, and Mastershop. Rule: All order lifecycle mutations occur strictly inside Strapi v5 backend services; Next.js frontend only consumes endpoints and never mutates supplier state directly.
- (decision) AD-2: Cryptographic Webhook Verification & Idempotent Payment Settlement. Binds: FR-PAY-01, FR-PAY-02, FR-PAY-04, NFR-SEC-03. Prevents: Duplicate fulfillment, replay attacks, and double order creation upon repeated webhook delivery. Rule: Webhook endpoints must verify HMAC SHA-256 signatures with WOMPI_INTEGRITY_SECRET/STRIPE_WEBHOOK_SECRET and check transactionId idempotency before executing status transitions.
- (decision) AD-3: Unified Cart with Hybrid Sourcing Partitioning. Binds: FR-CAT-03, FR-DROP-01..03, UJ-2. Prevents: Cart fragmentation or inventory collisions between local physical stock and dropshipped products. Rule: A single unified order encapsulates all purchased items, with line items partitioned into fulfillment groups (local vs mastershop_dropship) referencing mastershop_id and supplier_sku.
- (decision) AD-4: Asynchronous Mastershop Dispatch & Fault Isolation. Binds: FR-DROP-03, FR-DROP-04, FR-ADM-02. Prevents: Slow external API calls blocking webhook responses or transient Mastershop downtime breaking customer checkouts. Rule: Mastershop dispatch is triggered asynchronously after payment confirmation with exponential backoff and error capture in mastershop_data, with manual retry capability in Strapi admin.
- (decision) AD-5: Client-Side Cart State Persistence & DANE Hierarchy. Binds: FR-CART-01, FR-LOG-01, FR-LOG-02, NFR-UX-01. Prevents: Cart state loss during page transitions and inconsistent shipping pricing. Rule: Cart state is held in React Context + localStorage. Shipping matrix adheres to DANE Department->City taxonomy. Checkout totals calculated optimistically on client and strictly re-validated on server.
- (decision) AD-6: Zero-Cardholder-Data Boundary (PCI-DSS Scoping). Binds: NFR-SEC-01, FR-PAY-01, FR-PAY-02. Prevents: PCI compliance scope expansion or exposure of credit card / Nequi security PINs. Rule: No credit card PAN, CVV, or banking credentials shall touch or be stored on Prana Market servers. All card tokenization and Nequi push authorizations happen directly through Wompi / Stripe client SDKs.
- (decision) AD-7: Cloudinary Media Transformation & Responsive Next/Image. Binds: NFR-PERF-01..03, FR-CAT-02. Prevents: Mobile LCP degradation from uncompressed beauty catalog imagery. Rule: Product images uploaded to Cloudinary via Strapi provider; rendered in Next.js using next/image with AVIF/WebP formats, standard breakpoints (640, 768, 1024, 1280), and lazy-loading with blur placeholder.
- (version) Frontend: Next.js 16.1.2, React 19.1.0, Tailwind CSS 4.x, Framer Motion 12.29.2, Lucide React 0.563.0, Stripe SDK 18.5.0; Backend: Strapi 5.33.1, PostgreSQL 8.8.0 (pg), Cloudinary Provider 5.33.4, Node-cron 4.2.1, Nodemailer 7.0.12
- (assumption) [ASSUMPTION-01] Mastershop provides REST endpoints and webhook triggers for automated catalog retrieval, inventory lookup, and order placement with API key authentication.
- (assumption) [ASSUMPTION-02] Wompi Sandbox and Production keys are provided via environment variables with SHA-256 HMAC integrity secret for server-side payment validation.
